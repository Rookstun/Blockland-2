Console command names changed in current Brickadia: clear all = `br.World.ClearAll` (NOT Bricks.ClearAll), region = `br.World.ClearRegion`, save = `br.World.SaveAs "name"`, owner clear = `br.Bricks.Clear <id> 1`. Find others by scanning the server binary for `br.` strings (no strings/help command works).

Server accepts ~5000 bricks/sec (user-stated); map chunks are 5000 bricks, `bridge/tools/loadmap.sh` streams `bridge/map/chunk_*.json` paced only by captureMs. "Missing brick type to create brick" = procedural size off grid: x/y half-extents must be multiples of 5, z multiple of 2 (mapgen.mjs now throws on these). Orientation code = direction*4+rotation; Omegga's `dist/util/brick/constants.js` translationTable[code] maps local→world axes (verified in-game). PB_DefaultMicroWedge is natively a SIDE wedge (solid x+y<=0, extruded along local z) — tip it for slopes; PB_DefaultMicroWedgeCorner stands upright natively (apex over local -x-y), only yaw it. Size is in local axes, so permute it with the orientation or the AABB overlaps and the brick is rejected. Read back player-placed bricks with `br.Prefab.SaveRegion "name" cx cy cz ex ey ez 0` → Saved/Prefabs/name.brz, parse with WorldReader. PB_DefaultRamp still unverified. Bricks with components (e.g. B_Bot_Spawn_Point bot settings) can't be written by the bridge: save the player's brick as a prefab (SaveRegion), then `br.Prefab.Load "name" x y z 0 16` stamps it exactly at x,y,z, ownerless (so clear by ClearRegion, not owner). Dungeon enemies = prefabs dungeon_spawner_1..7 (Handaxe→Battleaxe skeletons, user-built); placement list `bridge/map/spawners_placed.json`, loader `bridge/tools/load-spawners.mjs NEW OLD | node job.mjs`. Media plugin (2026-10-02, local `brickadia/omegga-media/`, server `plugins/media`): /playvideo (yt-dlp in bin/, ffmpeg frames → double-buffered brick screen), /playaudio (link → self-playing speaker microchip built by heightmap2brz `bin/heightmap` in voice/bank/midi mode; midi = basic-pitch in `media/venv` + tomidi.py first; or built-in BA_* sound). The custom heightmap 0.20 binary (also chatbot/bin) does audio (--audio-mode voice|bank), --midi, and video (--anim-mode brick: flat micro-brick screen, ~38k gates at 80px) as in-game wire devices. A heightmap world .brz loads via `Prefab.Load ref x y z 0 16` landing at exactly file coords + (x,y,z). yt-dlp needs `--js-runtimes node:<path>` for YouTube; prefer HLS (protocol^=m3u8) formats, dash ones 403 at random. Facts learned: legacy writeBrzLegacy prefabs FAIL `Prefab.Load ... 1` ("no valid metadata") — use `new brs.World()` + `makePrefab()` for absolute placement. Sounds = Component_AudioEmitter on B_1x1F_Speaker, asset via `toBrz({externalAssets:[{type:'BrickAudioDescriptor',name}]})`; game clamps MaxDistance≤400, InnerRadius≤100, Volume≤2, Pitch 0.1–4. Bridge has an `emit` op to fire `cmd:<name>` as a player for testing. getPosition can return ~(0,0,0) while respawning.

`.brdb` worlds are SQLite virtual filesystems (folders/files/blobs/revisions), bricks in compressed `.mps` chunks — don't write them live; use the bridge. Related: [[brickadia-pikmin-project]]
